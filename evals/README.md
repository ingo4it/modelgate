# evals

The release gate (ADR-0002). A change to prompts, retrieval, chunking, or the
model config doesn't ship unless the eval suite still clears its targets.

## Layout

```
dataset/cases.jsonl   versioned question/reference/expected-source cases
scorers/              hit-rate@5 (set overlap), answer-relevance (embedding
                      cosine), faithfulness (LLM judge, heuristic fallback)
support/memory-store  in-memory VectorSearch so the suite needs no database
fixtures/             recorded model responses for the offline CI path
results/latest.json   last run, regenerated by `pnpm eval`
run.ts                the harness
```

## Running

```bash
pnpm eval                      # offline: FixtureEmbedder + MemoryVectorStore + fixtures
pnpm eval --provider anthropic # real Voyage + Anthropic
pnpm eval --gate               # exit non-zero if any aggregate misses target (CI)
```

## Metrics & targets

| Metric | How it's scored | Target |
| --- | --- | --- |
| Faithfulness | LLM judge: fraction of answer claims the cited context supports (heuristic: citation density + abstain check when offline) | ≥ 0.90 |
| Answer relevance | cosine(answer, reference) in embedding space; capped at 0.5 if a `mustContain` phrase is missing | ≥ 0.85 |
| Retrieval hit-rate @5 | of the sources a case needs, how many are in the top-5 retrieved chunks | ≥ 0.80 |
| p95 latency | wall-clock per case, cache disabled | ≤ 4000 ms |

## Versioning the dataset

`cases.jsonl` is append-mostly and reviewed like code. Each case is one line so
diffs are readable. When the corpus changes, cases that named a removed source
are updated in the same PR. The `id` is stable — never renumber, so historical
`results/` stay comparable.
